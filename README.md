# avia-watcher

24/7 Python-демон: следит за ценами на авиабилеты по заданным маршрутам через
официальный бесплатный партнёрский API Travelpayouts и присылает уведомление
в Telegram, когда цена аномально (по умолчанию — вдвое) ниже скользящей
медианы истории этого маршрута.

## Как это работает и в чём отличие от обычных трекеров цен

Обычные трекеры цен уведомляют о любом снижении цены на отслеживаемом
маршруте. Этот скрипт делает другое: сравнивает
каждую новую цену со статистической медианой истории конкретного маршрута и
шлёт алерт только при существенном отклонении (порог настраивается) — то
есть фильтрует рутинные колебания цен и оставляет вероятные "глюк-тарифы"
или ошибки в разметке цен. Дополнительно можно отслеживать сразу несколько
аэропортов вылета против нескольких направлений одним процессом (см.
"Настройка маршрутов" ниже).

**Отдельно, независимо от статистики**: любой билет в Москву (destination
`MOW`) не дороже `MOSCOW_PRICE_CEILING_RUB` (по умолчанию 4500₽, в
`config.py`) шлётся всегда — даже если это не аномалия, а обычная цена для
маршрута. Это не отменяет проверку по медиане выше — обе работают
одновременно, более дешёвые аномалии продолжают ловиться тем же общим
механизмом.

**Честно про ограничения** (см. также `PLAN.md`): это не гарантия обогнать
профессиональные сервисы поиска дешёвых билетов с большей инфраструктурой —
это лучше, чем ручная проверка, но не 100%-й отлов всех аномалий. Источник
данных — один бесплатный API Travelpayouts, а не скрейпинг
десятков сайтов (см. `PLAN.md` про то, почему это осознанный выбор, а не
недоработка).

## Установка

```bash
pip install -r requirements.txt
cp .env.example .env
```

### 1. Токен Travelpayouts

1. Зарегистрируйтесь на [travelpayouts.com](https://www.travelpayouts.com/) —
   бесплатно.
2. В личном кабинете найдите раздел API — там токен и MARKER (партнёрский
   идентификатор, используется только для резервной ссылки на поиск, если
   API не вернёт точную ссылку на конкретный тариф).
3. Впишите оба значения в `.env` (`TRAVELPAYOUTS_TOKEN`, `TRAVELPAYOUTS_MARKER`).

### 2. Telegram-бот

1. Напишите [@BotFather](https://t.me/BotFather) в Telegram, отправьте
   `/newbot`, следуйте инструкциям — получите `TELEGRAM_BOT_TOKEN`.
2. Напишите своему новому боту любое сообщение (например, "привет") — без
   этого бот не сможет писать вам первым.
3. Откройте в браузере
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates` и найдите в ответе
   `"chat":{"id": ...}` — это и есть `TELEGRAM_CHAT_ID`.
4. Впишите оба значения в `.env`.

### 3. Настройка маршрутов — `config.py`

**Проверьте IATA-коды городов и даты перед запуском** — скрипт их не
валидирует, неверный код просто даст пустые результаты.

```python
ORIGINS = ["NAL"]        # можно несколько: ["NAL", "MRV", "OGZ", "GRV"]
DESTINATIONS = ["MOW"]   # можно несколько направлений
DEPARTURE_AT = "2026-11"
RETURN_AT = None         # None = только в одну сторону
```

`ROUTES` собирается автоматически как декартово произведение
`ORIGINS × DESTINATIONS` — не нужно вручную дублировать словари для каждой
комбинации. Остальные параметры (`ANOMALY_THRESHOLD`, `MIN_HISTORY_SAMPLES`,
`POLL_INTERVAL_SECONDS` и т.д.) тоже в `config.py`, с комментариями.

**Важно:** список из `config.py` используется только один раз — как
начальное заполнение базы при самом первом запуске. Дальше список маршрутов
живёт в `prices.db` и управляется прямо из Telegram (см. ниже), правки
`ORIGINS`/`DESTINATIONS` после первого запуска уже не подхватятся сами.

## Управление маршрутами из Telegram

Под сообщениями бота — постоянная клавиатура с кнопками **📋 Список** и
**❓ Помощь**, а под каждым маршрутом в `/list` — кнопка **🗑 Удалить**, без
необходимости печатать команду. Добавление маршрута (нужны IATA-коды) всё
ещё текстом — Telegram не даёт удобно собрать свободный ввод в кнопки.

Команды (только из чата `TELEGRAM_CHAT_ID` — остальные молча игнорируются):

```
/list                               — список маршрутов, с кнопками удаления
/add ORIGIN DEST                    — добавить маршрут, auto-режим (см. ниже)
/add ORIGIN DEST YYYY-MM            — добавить на конкретный месяц/дату
/add ORIGIN DEST YYYY-MM YYYY-MM    — добавить туда-обратно
/remove N                           — удалить маршрут по номеру из /list
/help                                — подсказка по командам
```

**Auto-режим (по умолчанию, без даты)** — `/add NAL LED` мониторит
скользящее окно "текущий месяц + `MONTHS_AHEAD-1` следующих" (по умолчанию
3 месяца вперёд), пересчитываемое заново на каждом прогоне — то есть
реально "начиная с сегодня", а не застывает на месяце, в который маршрут
был добавлен. Указав дату явно — маршрут проверяется только на неё.

Изменения подхватываются на следующем прогоне (при GitHub Actions — в
течение ~5 минут, при своём сервере — почти сразу).

## Первый запуск — ОБЯЗАТЕЛЕН перед тем, как оставлять демон работать без присмотра

Точная схема JSON-ответа эндпоинта `prices_for_dates` API Travelpayouts не была
подтверждена официальной документацией на момент написания (см. `PLAN.md`,
раздел "Assumptions and sources") — только его существование и параметры
запроса. Реализация защищена (не падает), но может не находить цену, если
имя поля отличается от предположенного.

```bash
python watcher.py
```

Понаблюдайте за логом 1-2 минуты. Если видите строку уровня `ERROR` вида
`непустой ответ Travelpayouts, но не распознано поле цены` — это сигнал
остановиться (Ctrl+C) и поправить `fetch_cheapest()`/`build_purchase_link()`
в `watcher.py` под реальные имена полей, которые лог покажет в той же
строке. Если вместо этого видите `цена=<число>` — всё работает штатно.

## Проверка на реальном пороге

Временно поставьте в `config.py`:

```python
ANOMALY_THRESHOLD = 0.95
```

Запустите `python watcher.py`, дождитесь `MIN_HISTORY_SAMPLES` циклов опроса
по маршруту — должно прийти тестовое сообщение в Telegram. Не забудьте
вернуть порог обратно к рабочему значению (0.5 или своему).

## Запуск через GitHub Actions (бесплатно навсегда, без сервера и карты)

Вместо своего сервера — расписание внутри GitHub: `python watcher.py --once`
запускается по cron каждые ~5 минут в публичном репозитории (у публичных
репозиториев неограниченные бесплатные минуты Actions). История цен
(`prices.db`) переживает между запусками через `actions/cache`.

Уже настроено в этом проекте: `.github/workflows/watch.yml`. Всё, что нужно —
запушить репозиторий на GitHub и прописать токены в Settings → Secrets and
variables → Actions (`TRAVELPAYOUTS_TOKEN`, `TRAVELPAYOUTS_MARKER`,
`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`) — вместо `.env`, который на GitHub
не уедет (в `.gitignore`). Смотреть прогоны — вкладка **Actions** в репозитории.

Компромисс против своего 24/7-сервера: интервал ~5 минут вместо
`POLL_INTERVAL_SECONDS`(20с) из `config.py` — тот параметр действует только
для `main()` (режим ниже, для своего сервера), не для `--once`.

## Запуск как systemd-сервис (Linux VPS, 24/7)

```ini
# /etc/systemd/system/avia-watcher.service
[Unit]
Description=avia-watcher
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/avia-watcher
ExecStart=/usr/bin/python3 /opt/avia-watcher/watcher.py
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now avia-watcher
sudo journalctl -u avia-watcher -f   # смотреть логи
```

## Самодиагностика

- **Пульс раз в сутки**: короткое "жив, N маршрутов" в Telegram — чтобы
  тишина ("аномалий не нашлось") не путалась со "сломался и молчит".
- **Предупреждение о протухшем токене**: если Travelpayouts три раза подряд
  отвечает 401/403, бот один раз (не чаще раза в 6 часов) напишет в
  Telegram, что `TRAVELPAYOUTS_TOKEN` пора проверить.

## Данные и файлы

- `prices.db` — история цен и статусы алертов (SQLite), переживает
  перезапуск процесса. Не коммитится в git.
- `.env` — токены. **Никогда не коммитится в git** (см. `.gitignore`).
- `PLAN.md` / `PLAN-REVIEW-LOG.md` — план и протокол независимого ревью
  (Claude + Codex через claudex-loop), можно не трогать и не коммитить,
  оставлены для истории решений по проекту.
